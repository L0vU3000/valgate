# Hermes Agent — Valgate Monorepo

Hermes-specific operating rules for the Valgate monorepo. This file is read by Hermes Agent (walks parents up to the git root). It complements the shared `.cursorrules` / `AGENTS.md` files, which apply to all agents.

## 🗺️ Knowledge Map — READ FIRST
Read `KNOWLEDGE.md` at the repo root before working. It is the single index for where Valgate knowledge lives (design system, vault, Hindsight, Mem0, logs).

## 🧠 Memory Routing (Hermes-specific)

- **Personal facts** (who the user is, preferences) → Mem0 (local Qdrant).
- **Project facts** (architecture, decisions, design system) → Hindsight (project bank).
- **Stable environment facts** → Hermes built-in memory.
- Do NOT auto-store ambiguous content or default uncertain info into Hindsight.

## 🔄 Sync Architecture

Hermes orchestrates state across the VPS and the Mac via a bidirectional loop:

- **Hindsight API** — `127.0.0.1:8888` (VPS). Project memory bank.
- **Hindsight MCP Bridge** — `100.77.9.23:8081` (VPS, systemd). Exposes `/api/recall` and `/api/retain`.
- **Mac Worktree State API** — `100.92.171.48:8082` (Mac, LaunchAgent). Bearer-token auth; token at `~/.hermes/.mac-api-token`.
- **Hermes Inbox** — `~/.hermes/scripts/hermes-inbox.py` writes to a worktree's `.hermes/inbox.md` on the Mac.

**Worktree registry:** `vault/worktree-state.md` is the canonical view of worktree state.

## 🎨 Figma Bridge

Hermes can read/write the Figma file via the `open-figma-mcp` MCP server (plugin bridge):
- MCP server runs on the VPS, binds `127.0.0.1:18765`.
- Reverse SSH tunnel forwards the Mac's `18765` → VPS `18765`.
- The Figma plugin (on the Mac) connects to the bridge.
- Verify with `curl http://127.0.0.1:18765/health` — expect `{"ok":true,"plugin":true}`.
